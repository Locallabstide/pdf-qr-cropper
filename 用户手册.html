1这工具是干嘛的

假设你手里有一份 PDF，里面排了 100 个二维码——可能是桌贴、可能是优惠券、可能是设备标签。现在你需要把这 100 个二维码一个个单独抠出来，变成 100 张图片。

如果手动干，你得：截图 → 调整大小 → 裁剪成正方形 → 一个个命名 → 打包压缩。100 个，一晚上就没了。

这个工具就是干这件事的机器人：你把 PDF 丢进去，它自动找出里面所有的二维码，按正方形裁好，打包成一个 ZIP 给你下载。整个过程几秒钟。

它能做到什么

能力说明
自动找码不需要你标位置，它自己扫描每一页，找出所有二维码的坐标
精准裁切按二维码的"码眼"（三个角上的小方块）定位，裁成正方形，不歪不斜
自动编号按页码顺序 + 页内位置顺序，从 001.jpg 开始连续编号
手动改名编号只是一开始，你可随时改成自己想要的任何名字
批量打包所有图片压成一个 ZIP，一次下载搞定
完全离线识别引擎就装在这个 HTML 文件里，拔网线也能用
💡 你的文件很安全 所有处理都在你自己的浏览器里完成，PDF 和图片不会上传到任何服务器。不信的话，把网线拔了再试，功能一模一样。

它做不到什么

说清楚边界，免得你期待落空：

  • 不能识别二维码里的内容——什么"扫出来是 www.xxx.com"这种，它不管。它只负责"抠图"。
  • 不能读 PDF 里的普通文字——它没有 OCR 文字识别功能，只认二维码的码眼图案。
  • 不能认出手写、模糊、撕裂的二维码——图案太糊的话，机器也认不出来。
  • 不支持条形码——只处理二维码（QR Code），一维条形码会忽略。

4打开文件的两种方式

方式一：点击选择（传统方式）

点左侧「上传 PDF 文件」下面的方框 → 弹出系统的文件选择窗口 → 找到你的 PDF → 双击或点"打开"。

这个框只接受 .pdf 后缀的文件，其它格式选不到（或者选了会提示你）。

方式二：拖拽（推荐，快得多）

把 PDF 文件从文件夹里按住不放，拖到浏览器窗口上，整个窗口任意位置都行——不用对准那个上传框。

拖进来的时候，整个页面会蒙上一层半透明的黑色，中间弹出一个白框写着「松开鼠标，加载 PDF」。这时候松手，文件就开始加载了。

💡 为什么推荐拖拽 不用点、不用找、不用翻文件夹层级。PDF 就在桌面上？直接拖过来，两秒钟的事。

换一个 PDF 会怎样

放心换。加载新 PDF 的时候，上一次的处理结果会自动清空，包括右侧那一堆缩略图和导出的数据。不会混淆，也不会残留旧的二维码。

⚠️ 一次只能处理一个 PDF 这个工具是"一进一出"的：一次加载一个 PDF，处理完导出，再换下一个。想批量处理多个 PDF，请分多次操作。

5三个参数怎么填

左侧「2. 处理参数」卡片里有三个可调项。默认值已经调到最优，90% 的情况你什么都不用改。但如果你想搞清楚每个参数在干什么，往下看。

① 渲染 DPI（决定识别和裁切清晰度）

三选一的下拉框：

选项什么意思什么时候选
200 DPI（快）把 PDF 页面渲染成较低分辨率的图，处理快页数特别多、想快点出结果、二维码本身很清楚
300 DPI（标准）标准印刷级清晰度（默认）绝大多数情况，不用改
400 DPI（极精）更高分辨率，像素更多二维码很小、印得很密，300 认不出来时试试

简单说：DPI 越高，抠出来的图越清晰、越容易认出来，但处理越慢、越吃内存。

② 起始编号

一个数字输入框，默认 1。

它决定第一个二维码叫什么名字。填 1，就是 001.jpg、002.jpg…；填 100，就是 100.jpg、101.jpg…

为什么要改？比如你要给三份 PDF 提取，想让编号连起来不重复：第一份用 1 开始（001–050），第二份就从 51 开始（051–100），第三份从 101 开始。这样合起来一套编号，整整齐齐。

③ 并发页数

下拉框可选 1 / 2 / 3 / 4 / 6 / 8，默认按你电脑的 CPU 核数自动设定（一般 3 或 4）。

意思是"同时处理几页"。设成 3，就是三页一起开工，谁先做完谁接着领下一页。

设置效果
1（串行）一页一页老老实实做。最慢，但最省内存，老电脑选这个不容易卡
3（推荐）速度和内存的平衡点
6 / 8多核电脑的满速模式，榨干 CPU。内存小的电脑可能卡顿
💡 一个容易误解的点 这里的"并发"只管页面渲染。真正耗时间的"找二维码"环节，工具会自动按你 CPU 的核数另外开一批线程并行跑，不受这个选项影响。所以选 3 已经能跑得飞快了。
⚠️ 电脑卡住了怎么办 如果处理时浏览器明显卡顿、风扇狂转，把「并发页数」降到 2 或 1，再把「渲染 DPI」降到 200，重来一次。

这个数字是实时的——你删掉几张，它立刻跟着变。

编号顺序是怎么定的

按"页码优先、页内从上到下从左到右"来：

  • 第 1 页的 3 个码 → 001、002、003
  • 第 2 页的 4 个码 → 004、005、006、007

页内的顺序是阅读顺序：先比垂直位置，上面的排前面；同一行的，左边的排前面。这跟你看书从左到右、从上到下的习惯是一致的，所以核对起来很直观。

💡 没有识别出二维码？ 如果某个页面一个码都没找到，它就直接不贡献结果，不会弹错误。如果你发现整份 PDF 一个都没出来，先跳到第 9 章看看。

7改名字和删掉不要的

改名字

直接点文件名输入框，把里面的文字改掉，然后点到别处（或者按回车），改好的名字就生效了。导出时 ZIP 里就是这个新名字。

关于名字的规则：

  • 支持中文——写「北京店-桌贴1」完全没问题
  • 支持字母、数字、下划线、连字符
  • 自动去掉非法字符—— \ / : * ? " < > | 这几个符号不能用在文件名里，你输了会被自动删掉
  • 清空会回退到编号——如果你把名字全删了，它会自动变回原来的编号（比如 007），不会变成空名字
  • 不用写 .jpg——后缀是自动加的，你只管写前面的部分

两张图重名了怎么办

比如你把两个都改成了「桌贴」。导出的时候，工具会自动处理：第一个是 桌贴.jpg，第二个自动变成 桌贴_2.jpg。如果还有第三个重名的，就是 桌贴_3.jpg。

不会有任何一个文件被覆盖丢掉。

删除

点卡片底部的「删除」，这张就没了，网格里其它卡片原地不动，不会整体重排闪一下。

如果把所有卡片都删光了，右侧会回到最初的「请选择 PDF 文件并开始处理」状态，导出按钮也会变灰——因为没东西可导了。

清空结果

网格左上角有个「清空结果」按钮，一点全清，比一个个删快。PDF 文件本身还留着，你可以重新点「开始检测并裁切」再跑一遍。

💡 改完名字要重新处理吗 不用。改名字只影响导出时 ZIP 里的文件名，跟识别和裁切没半点关系。改完直接导出就行。

8导出 ZIP 压缩包

点左下角「打包导出 ZIP」按钮，会经历两个阶段：

阶段一：生成 JPG（进度 0% → 80%） 文字显示「已生成 12/42」。这是在把每一张裁好的图真正编码成 JPG 文件。
42 张图，大概一秒钟左右跑完。
阶段二：打包 ZIP（进度 80% → 100%） 文字变成「正在打包 ZIP…」。把所有 JPG 装进一个压缩包。
完成后显示「导出完成」，右下角弹出绿色提示「ZIP 导出完成」。
浏览器自动下载 压缩包文件名规则：你的PDF文件名-crops.zip。
比如 PDF 叫「门店桌贴.pdf」，导出的就是「门店桌贴-crops.zip」。

ZIP 里面是什么

一层，没有多余的文件夹。直接就是一张张 JPG：

  • 001.jpg、002.jpg、003.jpg…
  • 或者你改过的名字，比如 北京店-桌贴1.jpg

图片规格

项目规格
格式JPG
形状正方形（严格按二维码的码眼外接方框裁）
留白码四周保留约 6% 的白色余量，不会紧贴着边
画质导出用较高画质（0.92），比屏幕上看到的缩略图更清楚
分辨率不强制固定值，取决于你选的 DPI 和二维码在 PDF 里的实际大小
💡 为什么不是固定分辨率 因为这是"抠图"不是"生成"。二维码在 PDF 里本来就多大，抠出来差不多就多大——强行拉伸到固定尺寸反而会糊。要更清楚，就把 DPI 调高，源头像素多了，抠出来自然更清楚。
⚠️ 有些浏览器的下载拦截 如果点了导出没反应，看一下浏览器地址栏右边有没有一个"已拦截下载"的小图标，点它允许即可。这是浏览器的安全策略，不是工具的问题。

9能认多小的二维码

这块是这工具最用心的地方，也是它识别率高的原因。搞懂这一章，你就知道遇到问题该往哪个方向调。

核心思路：先扫一遍，不够再放大

机器找二维码，跟人用眼睛找差不多——东西太小了看不清，得放大。但"无脑放到最大"会浪费时间。所以这工具的策略是三步走，够用就停：

轮次做法什么时候继续下一步
第 1 轮：原尺寸 用原始分辨率扫一遍 如果找到了一些码，先把它们记下来
第 2 轮：放大 2 倍 把整页图放大一倍再扫 如果这一轮找到了第 1 轮没找到的新码，说明确实有小码漏网 → 进第 3 轮
第 3 轮：放大 3 倍 再放大到三倍扫最后一遍 这轮扫完就结束了

另外还有一个救援机制：如果第 1 轮一个码都没找到，不管三七二十一直接跳到第 3 轮，用最高倍数再试一次。因为"整页都空"往往说明码都偏小，不救一下可能全丢了。

三种情况的实际效果

你的 PDF 情况实际会跑几轮结果
二维码都挺大，清楚（比如桌贴）只跑第 1 轮飞快，全找出来
大小混着，有几个偏小跑第 1、2、3 轮大的小的都能覆盖
整页都是小码，第 1 轮全空跑第 1 轮 → 直接跳第 3 轮救援成功，不至于颗粒无收
💡 所以大部分文件是"一遍过" 只有当真的存在小码的时候，才会付出多扫几遍的代价。这就是为什么页数多的文件通常也很快。

去重：同一个码不会被算两次

放大扫描的时候，同一个二维码可能在好几轮里都被找到。工具会自动去重——两个码的中心点距离很近（小于码宽度的 60%）就认为是同一个，只保留一份。所以你不会拿到重复的图。

识别不出来的三大原因

  1. 分辨率不够——二维码在 PDF 里本身就没几个像素。→ 把「渲染 DPI」调到 400 再试。
  2. 图案被破坏——有水印、被文字压住、印得糊、缺了个角。→ 这种机器也没办法，只能换源文件。
  3. 不是二维码——一维条形码、或者某种冷门的码制。→ 工具只认 QR Code。

10常见问题

双击之后打开的是记事本，一屏乱码，怎么办？
这是 Windows 把 .html 关联到记事本了。解决：右键这个文件 →「打开方式」→「选择其他应用」→ 选 Google Chrome 或 Microsoft Edge → 勾上「始终使用此应用打开 .html 文件」→ 确定。以后双击就直接进浏览器了。
拖进来一个 PDF，提示「请拖入 PDF 文件」？
说明你拖的不是 PDF。常见情况：拖的是 Word、Excel 或者一个文件夹；或者拖的是 PDF 的快捷方式（.lnk）而不是文件本身。检查一下后缀是不是 .pdf。
提示「PDF 加载失败」，怎么办？
两种可能：
① PDF 文件损坏或不完整 → 用别的阅读器（比如 Adobe Reader）打开试试，打不开就是文件本身问题。
② PDF 有加密或密码保护 → 这工具处理不了加密 PDF，请先用别的工具去掉密码。
「开始检测并裁切」按钮是灰的，点不动？
因为还没加载 PDF。先在左侧「1. 选择 PDF」里选一个文件，按钮就会亮起来。
「打包导出 ZIP」按钮是灰的，点不动？
因为结果列表是空的。要么还没点「开始检测并裁切」，要么处理后一个二维码都没找到，要么你把结果全删光了。
处理完了，但一个二维码都没找到？
按这个顺序查：
① 确认这份 PDF 里真的有二维码（先在阅读器里翻一遍）；
② 把「渲染 DPI」调到 400，重新处理；
③ 如果 PDF 是扫描件、本身就是很糊的图片，那基本没救了，需要找到原始的电子版 PDF。
二维码找出来了，但裁得有点歪 / 边上缺一点点？
裁切是按二维码的三个"码眼"定位的，如果二维码本身印得歪、或者在 PDF 里做了旋转变形，裁出来的方框可能就会带一点点偏。
另外，工具已经预留了约 6% 的白色边距来包容这种误差。如果还是不满意，把「渲染 DPI」调高重试通常会更准。
处理到一半没动静了，进度条卡住？
① 先耐心等——400 DPI 且页数多时，单页可能要好几秒；
② 看页面右下角有没有红色错误提示；
③ 如果有某一页处理失败，工具会在最后告诉你「X 页处理失败（第 A、B 页）」，其它页的结果不受影响；
④ 实在卡死就刷新页面重来，把「并发页数」降到 1、DPI 降到 200。
能一次处理好几个 PDF 吗？
不能，一次一个。处理完导出，再拖下一个 PDF 进去继续。想批量的话，把「起始编号」衔接起来，编号就是连续的。
导出的图片能不能再清楚一点？
把「渲染 DPI」从 300 调到 400，重新跑一遍。抠出来的图会明显更锐利。
注意：如果源 PDF 里的二维码本身就是低分辨率的位图，调到 400 也不会变清楚——因为源头就没有那么多信息。
断网了还能用吗？
能。识别引擎和 PDF 解析引擎都是内嵌在这个 HTML 文件里的（文件大概 4 MB 就是这么来的），不请求任何网络资源。可以当成一个离线软件放在 U 盘里到处用。
处理会消耗流量吗？数据会被上传吗？
不会。全程零网络请求。PDF 和图片都只在你的浏览器内存里流转，关掉页面就没了。
想验证：打开浏览器的开发者工具（F12）→ Network 面板 → 清空 → 完整跑一遍 → 看不到任何对外请求。
手机上能用吗？
不推荐。手机浏览器处理大 PDF 很容易内存不足闪退。这工具是给电脑用的（Chrome / Edge）。
改完文件名，可以直接在网页里看到新名字排列吗？
卡片位置不会重排（不会因为你改名就跳到别处），但输入框里显示的就是新名字，导出时用的也是新名字，放心。

11术语小词典

手册里出现的几个词，用大白话解释一遍。

DPI
每英寸多少个点，衡量清晰度的单位。数字越大越精细，文件也越大。印刷常用 300 DPI。这里选 300 表示"按印刷标准把 PDF 页渲染成图片"。
码眼 / 定位图案
二维码三个角上那三个"回"字形的大方块。它们的作用是让机器知道"这是个二维码、它有多大、它有没有被转歪"。这工具就是靠找这三个方块来定位并裁出正方形的。
渲染
把 PDF 这种"矢量描述"变成屏幕上/图片里一个个真实的像素点。渲染 DPI 越高，出来的图越大越清楚。
升采样 / 放大扫描
把图片放大后再送去识别。目的是让小二维码"变大"，机器更容易看清楚。代价是慢。
去重
同一个二维码在多轮扫描里被重复找到了，去掉多余的，只留一个。避免你拿到重复图片。
Web Worker / 多核并行
浏览器里可以同时开好几个"隐形的小帮手"一起算。这工具用它们同时处理多页、同时识别，所以比一个个排队快得多。
并发
同时干几件事。并发 3 就是同时处理 3 页。
ZIP
一种压缩包格式。把几十张图片装进一个文件，既方便下载，也能省点体积。
JPG / JPEG
最常见的图片格式。体积小，适合照片和这类二维码图。
Toast / 浮层提示
屏幕角落飘出来、几秒钟自动消失的小提示框。这里指右下角那个。
码眼定位
不靠猜测、不靠画框，而是直接找到二维码的定位图案来算位置。比"按固定间距切割"精准得多。
